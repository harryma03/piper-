# 模拟 RGB-D 到圆柱抓取

本试验在 Gazebo 和 ROS 域 183 中运行，场景、相机、规划和控制均为仿真。它用随机位置的红白圆柱验证一次识别到接触抬升的流程；当前不向实机发送任何数据或控制命令。

## 数据流

1. 场景生成器随机放置动态圆柱；位置只供场景设置和评估记录使用。
2. 腕部模拟 RGB-D 相机采集同步彩色图、深度和内参。图像通过本地桥节点转成与现有视觉模块一致的格式。
3. `observe_cylinder.py` 识别红色侧面，在相机点云中拟合圆柱，用图像时刻的**仿真 TF** 转到基座系。识别结果写入本地 JSON，不发布坐标话题。
4. `run_grasp.py --vision-observation` 只用该观测生成目标碰撞体和抓取候选，进行 MoveIt 规划与仿真控制；不以 Gazebo 真值代替识别结果。
5. 评估读取 Gazebo 物体状态，计算识别误差、实际抬升和保持情况。没有固定连接或瞬移附着物体。

完整中心的 Z 和轴向来自任务先验：圆柱直径 46 mm、高 80 mm，竖立在 z=-0.15 m 的平面上。XY 来自可见红色曲面的拟合；这不是任意形状的 6D 位姿识别。检测会核对拟合直径、轴向、图像与 TF/关节时间戳和采集后的关节状态，不合格时拒绝抓取。

## 运行随机批次

在项目根目录加载 ROS 与工作区后运行：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
PYTHONPATH="$PWD/src/piperx_lab:$PYTHONPATH" \
  python3 scripts/run_gazebo_vision_grasp_batch.py --trials 10 --seed 42
```

默认在 `x=0.40–0.50 m、y=-0.05–0.05 m` 的工作区域内均匀随机选择圆柱位置，每次重启仿真以复位。该范围只是本次测试区域，并不代表机械臂的完整可达空间。种子控制位置采样，不能保证物理仿真每次完全一致。

批次保存在本地 `records/gazebo_vision_grasp/<时间>/`。每轮保存场景日志、观测 JSON 与标注图、动作日志和结果 JSON；`summary.json` 在每轮结束后更新。场景启动、识别、规划或抓取失败均计入总尝试，不用真值回退。

成功要求：闭合和抬升期间分别检测到双指接触，物体实际抬升超过 70 mm、水平偏移小于 60 mm，最后 10 个采样点最大倾角小于 15°、相对首点最大位移小于 3 mm。这些阈值用于本仿真检查，少量试验不能代表普遍成功率。

相机为理想的针孔 RGB-D，没有模拟 C1W 的畸变、量程噪声或反光误差；机械臂重力关闭，夹指控制和摩擦参数也未做实物标定。仿真结果不能直接当作实机表现。

## 本次随机结果（2026-10-29）

固定位置采样种子 42，在上述区域独立重置场景 10 次：识别 10/10，完整抓取验收 8/10（80%）。10 次中心估计与仿真物体初始中心的误差为 1.07–1.28 mm、均值 1.18 mm；其中中心高度由已知平面及尺寸计算，不能理解为三个坐标都经过独立深度真值验证。

第 4、10 轮均识别成功，闭合和抬升期间双指有接触，抬升过程中采样到的物体高度上升约 93 mm；但后续关节反馈检查超时，没有完成末态稳定性验收，按失败统计。两个失败位置都位于本次采样范围的同一侧，但样本很少，不能据此确定工作空间边界或故障根因。为方便后续排查，后续运行会在反馈超时时记录各关节末态误差。

结果和位置图保存在本机 `records/gazebo_vision_grasp/random_seed42/`，其中每轮 `observation.json` 来自模拟相机、`result.json` 含仅供评估的 Gazebo 真值。该批结果未自动提交到仓库。
