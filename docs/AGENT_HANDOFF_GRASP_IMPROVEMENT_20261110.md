## 一、目标和当前结论

首要目标是解决实机夹爪没有到达指定位置的问题，并形成可重复验证的 RGB-D → 目标观测 → 抓取候选 → 运动规划 → 执行与结果验收流程。先保证到点准确，再优化抓取姿态和成功率。

设备：AgileX Piper 六轴机械臂、原厂 agx_gripper、随第六轴转动的 PointSpread OKULO-C1W-H106/940。开发工作区为 `/home/co/ROBOT_PIPERX`；该目录当前未附带 Git 历史，不要误把另一个 SDK 目录或师兄的 piper_real 仓库当作本项目。目标仓库为 https://github.com/harryma03/piper- ，从实际最新分支建立 `codex/` 开头的实现分支。

必须保留的事实：

- 今天至少两次实机抓取动作已执行，现场操作者确认均未成功，夹爪未到指定位置，偏差较大；没有独立测量误差方向和数值，根因未确定。
- `records/real_grasp_20261110/execution_result3.json` 与 `adjusted_grasp_result.json` 中的 `executed` 仅说明动作流程执行，`lift_m=0.05` 是命令值，不能据此宣称物体被抬起。
- 仿真中长方体移近 5 cm 后抓起；较远位置的部分模型候选没有预抓取逆解。较远圆柱改用几何候选后物理抓起，说明不能把该位置直接宣布为不可达。
- 随机圆柱有单次完整仿真成功，不能据此推断随机物体或实机成功率。
- YOLO 已接入只读点云界面，尚未接入自动抓取感知服务；有误识别实例。
- 相机曾出现 USB 枚举错误与反复断连，后来恢复。实现必须将断流、恢复和观测过期纳入测试。

## 二、已核实的问题和代码入口

1. `src/piperx_lab/piperx_lab/handeye_solve.py` 当前 `quality_pass` 允许固定板位置散差小于 20 mm、角度散差小于 5°、平均重投影 RMS 小于 2 px。它是内部一致性检查，不是独立的抓取精度验收。
2. `src/piperx_lab/piperx_lab/cylinder_grasp.py::model_tip_transform` 使用模型中的夹指参考系均值作为夹指端部参考；`graspnet_adapter.py::convert_grasps` 也声明为初始几何近似。实机接触 TCP、指垫、开口和网络夹爪定义之间的对应关系还需验证，不能认定当前实现必错，也不能默认正确。
3. `sim/gazebo/grasp/run_closed_loop.py` 在分段接近中仅在更新成功时处理目标变化，更新失败可以继续使用旧目标；重规划分支还引用了未定义的 `radius`。触发目标移动后可能异常退出。
4. `sim/gazebo/grasp/perception_service.py::wait_bundle` 的参数主要控制等待截止时间，代码没有据此检查返回图像距当前 ROS 时间的真实年龄；`take_bundle` 取缓存中最旧的完整帧。帧与关节/TF 同步并不能证明帧是最新的。
5. 预抓取距离主要是固定的 6、8、10 cm，缩短距离的试验曾因候选超过 40 上限而中断。网络分数排序不能替代机器人完整路径可达性。
6. 仿真圆柱某次 560 个模型预测中，554 个因开口超限被拒、6 个因目标点支持不足被拒。应检查网络夹爪与 Piper 定义，不能简单放宽限制。
7. 实机候选和执行产物中存在不同开口数值及临时调整字段；实现者应追溯生成/执行代码，核对“预测物体宽度、期望双指总开口、单指位移、关节反馈”各自定义。不要凭日志数值自行猜测一个常数补偿。

相关源文件：`transforms.py`、`target_base.py`、`camera_target.py`、`rgbd_geometry.py`、`grasp_candidate_filter.py`、`grasp_candidates.py`、`gripper_policy.py`、`object_observation.py`、`sim/gazebo/grasp/run_grasp.py`。师兄 `/home/co/piper_real` 只能作为接口参考，不能直接使用其手眼外参或默认实机自动使能启动配置。

## 三、P0：先解决实机到点偏差

### P0-A：可追溯的坐标与标定配置

实施内容：

- 明确约定 `T_A_B` 表示把 B 系坐标变换到 A 系。统一记录图像光学系、SDK 点云系、基座、link6、规划 TCP 与夹指接触参考系。
- 相机输入必须同时携带图像、深度/组织点云、内参、时间戳、真实 `frame_id`、相机序列号、来源、图像时刻关节状态与 TF。实机优先使用当前 C1W SDK XYZ，保留鱼眼模型支持。
- 对彩色光学系、对齐图像标签、深度系和 SDK 点云系的关系做实际核对；确认轴向和对齐后才使用别名映射，禁止仅修改标签掩盖坐标差异。
- 为手眼结果和 TCP 结果保存不可覆盖的版本、校验值、采集会话与配置来源；明确选中哪个版本，不要依赖“目录中最新文件”。记录相机安装改变情况，禁止混用不同安装条件的样本。
- 将内部一致性通过与独立定位验收通过分成两个状态。结果允许显式失败/待验证；不能只改阈值让它变绿。

验收标准：

- 给出完整坐标变换链和至少一个数值例子，可追溯到输入帧、关节状态、外参和 TCP。
- 离线测试覆盖变换方向、逆变换、单位、错 frame_id、旧标定版本和错误序列号；错误输入明确拒绝。
- 用固定板角点或可重复定位的已知点做独立验证，参考点/测量方法与其误差需记录；不要用一片颜色可见面的中位点代替同一个物理参考点。
- 实机验收目标：至少 10 个静止姿态，覆盖不同腕部朝向与视角；报告误差 XYZ 分量、均值、P95、最大值。以 P95 ≤ 5 mm、最大 ≤ 10 mm 为第一阶段目标。测量工具精度必须足以支持该判断；达不到或无硬件则标记未通过/待现场验收，禁止虚构通过。

### P0-B：实测夹爪 TCP、轴向与开口

实施内容：

- 统一法兰、MoveIt 的 TCP 和两指接触区域中心的定义，测量或标定实际工具偏移；核对官方模型与实际夹爪、指垫是否一致。
- 开口参数只通过一个适配层转换，明确米/毫米、总开口/单指位移。网络预留间隙、夹爪机械零位和实际物体宽度各自有来源。
- 禁止使用临时“减常数”“吸附到目标中心”或猜测 Z 偏移来代替原因确认。校正必须有测量依据、版本和适用范围。
- 加入到点诊断模式：可先输出目标接触点、预抓取点、期望 TCP 和由关节反馈算出的实际 TCP，再生成低速无接触预览。实际运动按现场授权执行。

验收标准：

- 分别验证 X/Y/Z 正方向和工具旋转方向；在不同腕姿下，参考点不随错误工具偏移系统性漂移。
- 至少 3 个有尺量依据的夹爪开口位置，记录命令、反馈和实际双指间距；第一阶段开口误差目标 ≤ 2 mm。
- 至少 5 个独立已知点、每点至少 2 个可行腕姿，记录实际接触参考中心误差；P95 ≤ 5 mm、最大 ≤ 10 mm 为第一阶段目标。测量不足不能判通过。
- 使用反馈确认位置，不将 MoveIt 返回成功或仿真 FK 自洽当作实机精度证据。

### P0-C：新鲜度、断流与失败后的停止

实施内容：

- 按 ROS 时钟/仿真时钟检查图像年龄、未来时间戳、同步误差及候选生成后的有效期；耗时推理完成后再次检查，必要时重新观察。
- 改为优先使用最新的完整同步帧，避免积压缓存导致一直处理旧帧。
- 修复未定义 `radius`；跟踪丢失、相机断连、超时、无新候选或时间回退时，状态机停止推进并输出原因。不要在没有目标证据时继续沿旧目标接近。
- 支持相机断连后清空旧缓存并重新建会话；恢复后必须有新帧，不允许复用断连前坐标。

验收标准：

- 将阈值做成明确配置并附理由；初始建议图像/反馈同步误差 ≤ 100 ms、静止单次观测年龄 ≤ 500 ms。模型推理超时必须重新观测或拒绝，不能靠扩大年龄阈值掩盖问题。根据真实频率修订阈值时须提供延迟测量。
- 自动测试覆盖旧帧、积压、目标消失、推理超时、USB 断流、无候选、仿真时钟回退和目标移动重规划。
- 上述异常发生后不得发送下一段接近/闭合动作；当前已在执行的轨迹是否已成功取消、实际停止耗时应单独报告，不能仅靠“不发下一段”宣称已立即停止。
- 目标移动测试确实进入重规划分支，不能用 `replan_count=0` 的静态成功证明闭环有效。

## 四、P1：候选与识别改进

### P1-A：机器人可达的多姿态候选

- 对上抓、斜抓、侧抓分别生成并评估；候选评估涵盖预抓取、完整接近、夹持后载荷抬升与环境碰撞。
- 自适应尝试 2/4/6/8 cm 等预抓取距离，短距离须保留必要的无接触路径检查，不能直接跳到物体内部。
- 排序考虑完整路径是否通过、碰撞间隙、关节余量、观测质量和几何接触支持。网络分数不是成功概率。
- 在生成阶段限制候选预算和去重，保持姿态多样性；不要把候选扩增后直接送入 40 上限检查导致整场崩溃。
- 网络、几何候选分别标记来源、排序依据和拒绝原因；保留相同检查强度。

验收：固定重跑远处长方体与移近 5 cm 的对照，再重跑远处圆柱。保持尺寸、朝向、物理参数可追溯。要求候选数始终满足契约、失败原因完整；抓起与否按真实接触/抬升结果报告，禁止预填成功。报告同一预抓取位置在多种姿态下的可达性，不能把一次 IK 无解当作整个物体位置不可达。

### P1-B：YOLO 分割进入统一观测接口

- 将颜色分割、点击深度分割和 YOLO 实例分割实现为可替换的目标选择器，后续统一接 `ObjectObservation`/点云和候选生成。
- YOLO 返回实例身份、类别、置信度、掩码、bbox、输入帧 ID/时间戳；同一帧提取深度/XYZ，不按新画面套旧掩码。
- 类别、颜色和几何先验分别保存。YOLO 标签是二维识别，不是六维位姿；圆柱轴向旋转等不可观测自由度明确表达。
- 支持多物体显式选择；低置信度、类别不支持或多目标歧义时允许人工点选。禁止用场景生成真值选定目标。

验收：至少覆盖一个非红色常见物体、两个实例选择、错帧掩码拒绝、深度无效、误识别/无检测回退；离线回放与仿真均需有证据。若仿真简化外观不被预训练模型识别，明确记录失败，不改成真值选目标。实机接入只读观测接口，实际抓取仍须满足 P0。

## 五、P1：结果可信和可复现

统一结果包含：run_id、backend、对象/观测来源、版本与配置校验值、阶段耗时、候选尝试与拒绝原因、已发送轨迹及反馈、抓取物理结果、保持结果、反馈收敛、失败阶段、失败原因。

- 将 `motion_executed`、`physical_grasp_success`、`hold_stable`、`feedback_settled`、`execution_complete` 分开。
- 无证据的物体抓起结果使用 `unknown`/null，不能直接赋成功或失败。
- 仿真可用接触和物体状态评估，但真值只能进入场景设置和评估，不能回流感知/规划。
- 实机需要可解释的抓取验证信号：视觉实际抬升/物体跟随、标定过的夹持反馈等。缺少可靠证据时保留待人工确认。
- 增加一次运行的复现命令、原始观测引用和可视化：RGB 掩码、目标点云、规划 TCP/夹指中心、候选姿态和失败阶段。
- 自动管理仿真实例，默认单场运行，结束时关闭所属子进程；保留场景须显式启用。不能用宽泛 pkill 清理其他任务，也不能堆积多个 Gazebo 导致系统卡顿。

验收：故障注入后结果 JSON 仍落盘，失败阶段非空；中断、启动失败、识别失败、规划失败与物理失败可区分；状态统计与逐条结果一致。两次历史实机记录作为“用户确认失败”的回放案例保留，不改写原始证据文件。

## 六、执行顺序与验证范围

1. 先交付 P0-A/B/C 的诊断和修复，以回放与仿真验证，完成独立定位验收后再扩大实机动作。
2. 先解决固定的 40 mm 方块、46×80 mm 圆柱，再扩展其他物体；暂不以 VLA 或更大的模型替代定位问题排查。
3. 基础回归至少包含当前相机模型、变换、仿真抓取、抓取审计、深度选点和网页错帧检查。基线运行过 30 项测试；实现者应记录实际版本和实际运行结果，而不是复制这个数字。
4. 使用固定种子形成 20 场独立仿真套件，覆盖远/近、左右、方块与圆柱、至少两种朝向和异常注入。候选、场景和参数完整记录；结果以全部请求场次为分母并列出排除项，逐项比较修改前后。物理抓取成功、反馈收敛与完整完成率分别统计。
5. 20 场用于回归观察，不预先要求某个成功率，也不能宣称任意物体能力；关键不变式是无过期目标推进、无真值泄漏、无漏记失败、无候选上限崩溃。
6. 现场没有设备或测量条件时，继续完成所有可离线实现和验证的工作；将实机验收留为明确待办，不能以此虚报完成，也不要因此停止其余独立任务。
